### § LAW-26: Cascade Coherence — The Graph Must Propagate

**Core why**: Documentation is not a set of files. It is a graph. Edges in the graph are propagation obligations. A change in any authoritative source creates obligations throughout its dependents. The failure mode is not a single wrong file — it is a system where each file looks correct individually while the system as a whole has silently diverged. False confidence in a diverged system is worse than visible failure.

**What it protects against**: The cascade miss. Updating README but not MEMORY.md. Adding a law narrative without creating the .init unit. Ending a session without an accretion stratum. Each of these is a partial update — and partial updates are insidious because they feel complete. The file was changed. The change was committed. But the graph was not honored.

**The three obligations this law encodes**:
1. **Propagation** — when any authoritative file changes, all dependents must be updated before the change is declared complete. Never stop after the first file and wait.
2. **Init unit integrity** — when the constitutional layer changes (new law, updated law), the .init unit must be created or updated WITH the narrative change. The hands (enforcement) must move with the declaration (text). A law without a .init unit has no hands.
3. **Accretion** — every meaningful session deposits a stratum in the sedimentation log. This is not documentation; it is stratigraphy. The accretion event is the final step of every cascade. It records what was deposited: what changed, what was discovered, what the system can do now that it could not before.

**The question it answers**: Is the change complete? Not "is the primary file updated?" — that is necessary but not sufficient. Complete means: every file in the propagation graph reflects the change. The .init unit exists. The accretion log has the stratum. Then the change is complete.

**The deeper truth**: The cascade is the discipline of honoring all edges before declaring a node update complete. Accretion is geological, not documentary — documentation describes what exists; stratigraphy records what was deposited. Both are required. Neither substitutes for the other. And when wisdom repatriates from daughter to mother, the full story travels as accretion — the carbon's words, the moment of recognition, the session arc — so that law-mother's record is self-contained across time. ### § LAW-27: Session Coherence Ladder — Climb Before You Build

**Core why**: Entropy accumulates between sessions silently. A Claude that begins building on an incoherent repo embeds the incoherence deeper into the new work. The ladder is the counter-force: ten specific, automatable checks that verify the ground is solid before any new work begins. The distinction is exact — init.d loads the constitution (what is right); the cascade propagates changes (what must follow); the ladder verifies coherence (what is currently true right now). All three mechanisms are required. None substitutes for the others.

**What it protects against**: Building new work on broken ground. Starting a session without verifying that the previous session's cascade completed. TOC entries that no longer match their headers. Laws declared but without .init units. Accretion gaps where meaningful sessions were not recorded. Broken internal links that erode trust in the entire document system. Stale metadata that gives false provenance.

**The eleven rungs and what each catches**:
1. **Navigation Scaffold** — *.md files >150 lines without TOC or back-to-top links (auto-fix)
2. **Init Unit Completeness** — declared laws without .init enforcement units (Obligation 2 of LAW 26)
3. **Cascade Chain Consistency** — diverged nodes in the propagation graph (must be consistent before building)
4. **Accretion Log Presence** — meaningful sessions without a stratum; missing docs/accretion.md
5. **Memory Residency Verification** — model-aware: full adoption daughters must have all memory in repo; lightweight daughters may use external auto-memory (sanctioned)
6. **Dead Reference Scan** — broken internal Markdown links and file path references
7. **TOC Sync** — orphaned TOC entries (no header) and unlinked headers (no TOC entry) (auto-fix)
8. **Constitutional Integrity** — law count mismatches, law-manage.py validate failures (LAW 18)
9. **Orphaned Init Unit Scan** — .init/law.N files with no declared LAW N (phantom enforcement)
10. **Stale Metadata Scan** — "Last Updated:" dates behind the git log modification date
11. **Repatriation Gap Detection** — daughter projects with unpatriated epiphanies, accretion strata, psychology articles, or universal laws (SKIP for law-mother)

**The question it answers**: Is the ground solid? Not "did the last session do good work?" — that may be true even when the repo has drifted. Not "does the constitution look right?" — init.d already verified that. The question is: right now, today, before we build anything new, is every structural invariant of this repo actually satisfied?

**The deeper truth**: The ladder teaches that correctness has a timestamp. What was correct at the end of last session may not be correct at the start of this one — not because anything went wrong, but because entropy accumulates in the gaps. The ladder is not a distrust of the previous session. It is an acknowledgment that coherence requires active maintenance, not just correct construction. Build with the ladder. Climb before you build. The State Report is not overhead — it is the foundation.
